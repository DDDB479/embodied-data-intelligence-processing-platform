# 生产升级 v3.0（2026-11-04）

本轮围绕可靠保存、真实检查、后台执行、批次操作和交付验证落地。保留明确的数据标注与审核步骤，未接入的算法继续标记为不可用。

## 日常操作

1. 在“数据接入”选择数据集总文件夹，确认 UMI / EGO / 遥操类型。平台按相对路径识别 `meta`、`data`、`video/videos`，保持 Episode 与相机关系。
2. 文件分成 4 MiB 分片上传，服务端逐片保存偏移与 SHA-256。断网、刷新或服务重启后，重新选择同一个总文件夹；本浏览器保留的导入草稿会复用批次和文件 ID，校验已上传分片后继续。更换浏览器、清除本地存储、改变文件列表或类型时，不承诺自动关联旧草稿。
3. 在“生产批次”执行完整质检。顶部“后台任务”可查看排队、执行、成功、失败和重启中断。刷新页面不会取消服务端任务。运行中的任务被服务重启打断时会明确显示“重启中断”，需点击重新执行；不伪称转换程序从中间位置恢复。
4. 在批次内打开问题：查看源文件路径、哈希、字段、从 0 开始的行号及实际值/期望值。修改源数据后“替换已修复文件”，或选总文件夹“补齐本批缺失文件”，随后对整批执行检查。仅填写处置说明不会消除数据错误。
5. 进入“数据标注”，填写并提交任务指令；进入“标注审核”通过或退回。指令按采集任务或数据集继承到 Episode。当前主要实现任务指令审核，不宣称完成自动位姿、语义或逐帧标注。
6. 门禁全部满足后提交批次验收，由负责人签署；选择 LeRobot v2.1、MCAP 或 Zarr 转换。独立解包回读通过后才提供当前有效 ZIP 下载。

旧版“已通过”不等于本版完成检查。缺少与当前源文件哈希绑定的完整检查证据时，批次验收和交付会被阻止，页面要求重新检查。原历史问题、标注、验收记录和源文件保留。

## 检查依据与范围

- 固定要求：原始文件存在、实际哈希与入库值一致、格式签名有效；按 `info.json` 和实际文件推断 Episode 与相机视角，逐项检出缺失片段。
- LeRobot Parquet：服务端 PyArrow 读取行与列；检查必需字段、空值、有限数值、动作/状态维度一致性、声明维度、非负索引、单 Episode、时间戳/帧/全局索引严格递增、帧缺口及声明 FPS 的采样间隔。最多返回 100 条定位证据，检查仍覆盖读取的数据。
- 视频：PyAV 实际逐帧解码，检查有效帧、时间戳顺序、分辨率、时长及与对应轨迹的时长偏差。同步容差默认取 0.1 秒与两个采样周期中的较大值。
- 默认黑屏候选：灰度均值 ≤ 8 的帧比例达到 95%；静止/冻结候选：缩小灰度帧平均差 ≤ 0.15，比例达到 98%，且至少 10 帧。这些是本项目的工程阈值，不是行业统一标准，不能代替任务成功判定。
- 质量工程师/负责人可对黑屏或静止候选填写至少 10 字的人工查看依据，确认可接受。判断绑定当前哈希并留审计记录，仅豁免这两类候选；解码失败、时间戳异常、同步错误等仍须修复。替换内容后旧人工判断失效。
- JSON/JSONL 完整解析；尚未接入完整解析器的其他容器会显示“解析器未接入”并阻断，而不会自动当作合格。当前最完整的生产验证路径是 LeRobot v2.1 轨迹与配套视频。
- 未配置机器人关节限位、标定真值或外部模型时，不宣称验证了物理安全、位姿精度或任务成功率。可选外部插件缺失会明示。

## 持久化与恢复

需要 Node.js 22.13+，推荐使用项目部署机上的 `runtime/node.exe`（24 LTS）。Python 依赖见 `tools/requirements-delivery.txt`，需包含 PyAV。

账号、业务状态、上传会话和后台任务保存在 `work/platform.sqlite`，使用 WAL 与事务。首次启动会先备份旧 `auth.json` / `server-state.json`，再迁移；旧 JSON 保留，不再作为运行时主数据。JSON 损坏或已初始化数据库丢失时，服务拒绝初始化空平台，避免隐藏数据丢失。

独立记录的并发修改可以合并；同字段冲突返回 409，要求刷新重试。仍是单机、单后台工作线程，不等于多实例数据库部署或经过压力验证的高并发系统。

“后台任务 → 创建完整备份”（或系统设置中的备份）会保存一致性数据库快照、账号、已引用的原始文件及交付文件，并生成逐文件 SHA-256 清单。任务只有复制及清单校验全部通过后才成功；失败目录标记为 `.partial`。备份在本机 `work/backups/full-*` 下，需要管理员另行复制到独立介质才能抵御整机磁盘损坏。正在上传的未提交分片不在完整备份恢复承诺内。

恢复必须在停止业务服务后进行，并选择一个**空目录**，不会覆盖已有数据：

```powershell
.\runtime\node.exe .\tools\storage-backup.cjs verify "D:\数据管理\work\backups\full-具体编号"
.\runtime\node.exe .\tools\storage-backup.cjs restore "D:\数据管理\work\backups\full-具体编号" "D:\数据管理\work-recovered"
$env:DATA_WORK_DIR = 'D:\数据管理\work-recovered'
.\runtime\node.exe .\serve.js
```

恢复会调整数据库内原工作目录的绝对路径，保留账号与业务数据，清除未完成上传会话。切换常驻启动脚本时也需保持同一个 `DATA_WORK_DIR`。不要在数据库迁移后直接运行旧版服务读取遗留 JSON；如需回退，应停止新服务后按升级前备份恢复一个独立目录。

顶部“后台任务 → 运维诊断”可查看 SQLite、认证、源文件目录、Python、视频解码器和可选插件状态。

## 交付验证的边界

每个新转换包包含源数据/标注/质检与验收证据、逐文件 SHA-256 清单和消费示例 `read_delivery.py`。转换器自检后，独立验证程序再解包验证 CRC、文件清单/哈希、全量视频解码、各格式轨迹回读、数值与时间戳，以及 Episode 相机完整性和视频帧/轨迹行数对应。下载前核对整包 SHA-256；数据或标注版本变化会使旧包失效。

LeRobot 为 v2.1；MCAP 为本项目 `embodied-json` profile，视频独立随包保留；Zarr 为 v2 列数组布局。未执行官方训练框架加载或真实机器人训练，报告明确记为 `downstreamTrainingLoader: not_configured`，接收方仍需确认字段约定与目标框架兼容性。
